# AutoReport Modern｜料號版

本版本與 `modern-work-order` 工單版分開維護。工作區分支為 `modern-part-number`。既有 GitHub Pages 網址仍對應原本的部署。

- 單筆查找和批次比對使用完整料號，包括已匯入的主料號及別名，例如 95 料號。CSV／一般 Excel 使用「料號」或「查詢值」欄位。Detail 優先使用 C 欄料號；對照有歧義時用 B 欄工單核對同一來源列，無料號對照時可採用唯一且完整的工單對照。
- 機種名稱 `TK14`、`TK16` 分別歸入 `Taroko 14`、`Taroko 16`。同料號對應多組 IC／機種時保留候選，需確認後才會補值。修改或確認補填以料號為範圍。
- 良率分析保持六製程和唯一 PPID 的計算口徑。料號良率依 C 欄料號與 IC／機種分組，同一組內依 PPID 去重。相同料號有多組機種時會分列。建議從本版重新比對原始檔，再分析新產出的 Detail。
- 料號版使用自己的本機對照資料庫、檔案庫、日期索引和分析快取。需要在此版重新匯入對照 Excel 及原始資料。料號版可另存和還原本機 JSON 備份。雲端服務啟用後，可用復原金鑰免帳號跨電腦備份。

## 跨電腦備份

在「雲端與本機備份」建立復原金鑰並另行保存，按「上傳本機資料」。另一台電腦開啟料號版，貼上同一把金鑰，即可下載 JSON 或還原至本機。還原會先下載本機備份，經確認才會取代這台電腦的料號版資料。雲端備份包含對照資料庫與檔案庫，不包含分析快取。備份上限 50 MiB（含 JSON 編碼）。

跨電腦備份由瀏覽器加密，Supabase 僅儲存加密內容。復原金鑰無法重設，請只交給有權查看與更新備份的人。網站不要求電子郵件或密碼，連線時會在背景建立匿名工作階段。

首次啟用時，Supabase 專案管理員須在 SQL Editor 執行 [料號版備份 migration](supabase/part-backup.sql)，並確認 Authentication 的 Anonymous Sign-Ins 已啟用。使用公開的 Supabase key 設定 `cloud/cloud-config.js`。這個步驟只建立料號版備份介面與資料表。

## 使用流程

系統從 Raw Data 讀取資料、比對料號 IC／機種，產生精簡 Detail，再依日期範圍計算良率與不良。品質分析及產品身份統計只納入以下六個製程：

1. DAF外觀
2. DAF熱壓投入
3. 功能一測試
4. 功能二測試
5. 外觀檢查點亮測試
6. 輝度機測試

「DAF投入」歸為「DAF熱壓投入」。常見製程別名會先正規化，例如「DAF外觀檢查」歸為「DAF外觀」、「功能一測」歸為「功能一測試」。其餘製程不納入精簡 Detail、投入 PPID、良率及不良統計。

## 作業流程

### 修改料號對照

在「單筆料號查找」展開「修改料號對照」。選擇或輸入料號，按「帶入目前對照」查看現有值，再由下拉選單選取 IC、機種及產品系列，或直接輸入新值。

「儲存並下載 Excel」會將更新寫入本瀏覽器資料庫，並下載這次修改的 Excel。從分析檔案庫重新開啟或下載報表時，會依最新對照重算。新版報表保留重算所需的來源資訊；舊的期間報表若找不到原始 Detail，請從原始檔重新分析。

### 1. 匯入 Raw Data 並比對

1. 在「Raw Data 原始檔案庫」匯入原始檔。
2. 執行料號 IC／機種比對。比對優先採用 Detail 的 **C 欄料號**，對照不足時依 **B 欄工單**確認；唯一匹配時才填入 **J 欄 IC**與 **K 欄機種**。
3. 比對結果只保留上述六個製程的資料列；原始 Raw Data 另存於原始檔案庫。
4. 同一批選取多個 Raw Data 檔時，系統會一併檢查跨檔 PPID 的 IC／機種對照是否一致。

多組候選、缺少比對資料或同一 PPID 對到不同 IC／機種時，系統不猜測機種，會轉入「料號 IC／機種補填」。請核對來源並完整填入 IC、機種，按「套用 IC／機種並重新產生結果」更新本批 Detail；確認輸出正確後，再按「確認補填並更新對照資料庫」。成功訊息會顯示已保存組數。只有具備原始工單的補填才能保存為同料號的長期對照。

同一 PPID 經過不同製程本身不算多片投入；只有 IC／機種對照確實互相矛盾時才需要人工處理。若不同原始檔可能包含互相衝突的 PPID 對照，請在同一批比對中一起選取，讓系統能檢查跨檔資料。

### 2. 日期區間分析

在「良率與不良分析」選擇 Detail 檔案庫及日、週或月的起訖範圍。先建立或更新日期索引，系統會自動選取範圍內有資料的檔案，並按日計算；PPID 在統計範圍內統一去重。此區間分析不受合併功能的 30 檔／100 MB 限制。

分析前請確認 Detail 已完成 IC／機種比對。缺少 J 欄 IC 或 K 欄機種的資料會列入待確認明細，不應以其產品別結果作正式判讀。跨 PPID 的 IC／機種衝突會另列於「PPID對照衝突」明細，應先回補正確對照再分析產品良率。

### 日／週／月不良率推移

建立／更新 Detail 日期索引後，選擇起訖期間與「推移橫軸」。按「只產出不良率項目推移圖」即可獨立分析。選「週」時依週日到週六逐週計算，首尾週僅納入所選日期。選「日」時在同一範圍逐日計算。選「月」時以曆月分組，每月分別去重 PPID，首尾月份依所選日期截斷。圖表已開啟時，切換橫軸會直接計算並保留仍適用的產品、製程與不良項目篩選。日期或週別各自對 PPID 去重並保存統計摘要，相同來源與期間可重用本機摘要。

可篩選產品、製程和不良項目。預設顯示不良數前五，也可改選不良率前五、全選或逐項勾選。圖例的 ON／OFF 控制曲線及 Excel 匯出。點圖例名稱看整段的機種／IC 明細（各點投入與不良加總，同一 PPID 跨點可能重複），點圓點看該日、週或月的機種／IC 明細。某製程有投入而該項無不良才記為 0%。日推移略過沒有來源投入的日期，週推移保留無投入週的空位。未完成或無法計算的區間留空。30 萬筆安全上限以橫軸單位（單日或單週）分開判斷，超限區間會列出原因，其餘照常計算。各點數值用於趨勢比較，跨期間 PPID 可能重複，各點投入不得相加當作整段唯一投入。

完整分析與獨立推移的「點位明細」按日期區間列出整段圖表數據。可在「料號明細」選單切換整段日期與單一日期區間。各點每片 PPID 歸到曲線採用的過站紀錄所屬料號，整段日期依料號加總各點的投入及不良後再計算比率。同一 PPID 跨點可能重複。未填工單另外列示。獨立推移的料號明細在展開後才逐區間讀取日期索引。

### 3. 合併 Detail

「合併 Detail 比對檔案庫」只處理含有 Detail 分頁的 XLSX。合併時可讀取 `Detail`、`Detail_2` 等 Detail 分頁；分頁標題須一致。重複的同日、同製程、同 PPID 紀錄會合併成一列，若重複列中有 FAIL，保留 FAIL 列。合併檔名會帶有資料日期區間及週別。

合併操作目前單次限制為 **1 至 30 個 XLSX，合計不超過 100 MB**。這項限制只適用合併功能，不適用上節的日期範圍分析。日／週／月區間分析應直接從檔案庫選取，不需要先把所有資料合併成單一超大檔。

## 目前運算規則

### PPID、良品與不良

- **唯一身份：** E 欄小板序號（PPID）。同一 PPID 即使跨日期或跨六個製程出現，在全範圍投入數只算 1 片；不可把各日、各站投入直接相加。
- **不良判定：** 任一納入資料列狀態為 `FAIL`，或 H 欄「不良項目」有文字，就把該 PPID 判為不良。狀態 `Scrap` 在計算時視同 `FAIL`，原始 Detail 文字不改寫。GOOD 列若填有不良項目也計為不良。
- **PPID 唯一分類：** 全範圍內只要該 PPID 在六製程的任一筆資料符合不良判定，整體就列為一片不良；否則為良品。
- **整體良率：** `(唯一投入 PPID - 唯一不良 PPID) ÷ 唯一投入 PPID`。
- **產品總良率：** 在 IC／機種一致的產品範圍內，以唯一良品 PPID ÷ 唯一投入 PPID。跨日期、跨製程的子層投入不能直接相加來推算產品總數。
- **製程良率：** 以該製程內不重複 PPID 為分母；同一 PPID 在該製程有任何不良紀錄即列不良。

### 不良項目與歸屬

- 每個不良 PPID 在全檔只歸屬一次，避免跨站重複計數。
- 優先採用該 PPID **依輸入檔案順序及原始列順序最先遇到的 FAIL**；若沒有 FAIL，才採用最先遇到且 H 欄有不良項目的 GOOD。此規則不會因較早的產出時間而重新挑選紀錄。
- H 欄完整內容視為一個不良項目，不會依逗號、頓號等分隔符切開。FAIL 沒有填不良項目時，顯示「【未填不良項目】」。
- 圖表的歸屬不良率以目前分組的投入 PPID 為分母；全檔不良率貢獻以全檔唯一投入 PPID 為分母。選定製程時按該製程 PPID 計算；未選製程時按所選範圍 PPID 聯集去重。
- 「總不良項目統計」按製程及不良項目分組，依目前篩選範圍統計整段期間。各製程跨日期對 PPID 去重，依推移圖的規則選取不良紀錄。每根柱的高度為該項不良 PPID ÷ 該製程總投入 PPID。相同不良名稱在不同製程各自顯示。
- 日期不良率與不良率項目推移圖各有「橫軸日期單位」。主分析按週時可切換週／日，按月時可切換月／週／日。各圖沿用所選起訖區間，依各自橫軸重新計算唯一投入 PPID 與不良率。
- 不良率項目推移圖的產品、製程及不良項目皆可複選，獨立推移也適用。多個產品在同一製程合併投入與不良 PPID。同一不良項目在不同製程各自分線，使用各製程唯一投入 PPID。點選圖例中的不良項目可查看目前期間有該項不良的機種／IC，點選圖上的圓點則查看該日、週或月。明細用橫向長條顯示各機種／IC 的不良率，並保留機種、IC、投入 PPID、不良 PPID 和不良率數值。分母為各機種／IC 在該製程的唯一投入 PPID，投入與該項不良 PPID 各自去重。圖例下方的「點位明細」預設收合，可展開查看該點位各項不良率與 PPID 數。
- 日期表／圖表會略過沒有投入 PPID 的日、週、月；有投入但沒有不良的期間則呈現 0%。

### 前段、後段與日期

- **前段：** DAF熱壓投入、DAF外觀、功能一測試。
- 每日良率圖先列前一週、當週，再列選定範圍的每一天；當週以所選結束日決定。週別有資料時顯示黃色長條，每日有資料時顯示紅色長條。缺資料的週或日期保留 X 軸空位與日期標籤，良率留白，投入顯示 0；整段無投入仍顯示完整座標軸與日期，Excel 圖表及日期欄同步保留。前週比較另讀取同一 Detail 檔案庫的可用資料，產品與 IC 必須相同。無投入或無法載入時不補造週數值，頁面會提示原因。
- **後段：** 輝度機測試、功能二測試、外觀檢查點亮測試。
- 前段／後段主要階段良率為該階段「有資料製程」良率的算術平均，各製程權重相同，沒有投入的製程不參與平均。
- 「階段良率比較」另列該階段 PPID 聯集去重後的良率及與製程平均的差異；兩種算法的分母不同，應依報表標示判讀。
- 前後段圖表標題及圖例使用「前段」「後段」。下載的「每日階段良率」及「已產生圖表」皆為原生 Excel 圖表，共用同一份數據。「每日階段良率」的良率欄直接寫入網站已算好的數值；「製程良率資料」供查核。修改「每日階段良率」頁的良率或 Target，兩頁圖表同步。
- **日：** 以產出時間所屬日計算。
- **週：** 週日到週六。每年度 W01 從 1 月 11 日當天或之後的第一個星期日起算。例如 **2026/10/25–10/31 為 2026-W42**。
- **月：** 依日曆月。區間投入以所選範圍的 PPID 聯集去重，不把每日投入直接相加。

## 資料保存與備份

- 每次送入比對的 Raw Data、比對結果及套用手動補填後的結果版本，都會保存在「比對歷史資料庫」。刪除日常檔案庫的原始檔或比對檔，不會刪除這些歷史版本；可從歷史資料下載或還原至檔案庫。更新前已刪除且沒有備份的資料無法追回。
- 預設的對照資料庫及匯入／比對／合併檔案庫保存在目前瀏覽器的本機儲存空間。更換瀏覽器或清除網站資料可能使本機資料消失。
- 「確認補填並更新對照資料庫」更新的是目前瀏覽器中的長期料號對照；它不會自動把 Raw Data 重新上傳。
- 可下載 SQLite 備份保存對照資料庫。檔案庫中的 Raw Data 與 Detail 檔請另行下載保存；SQLite 備份不包含這些 Excel 檔案。
- 清除本機資料庫會移除該瀏覽器的對照資料及檔案庫內容。清除前請先下載需要的備份與檔案。

## 分析範圍與效能

品質分析只讀取六個指定製程，避免其他製程資料增加計算量。日期範圍功能會按索引自動挑選涵蓋所選期間的檔案；期間良率報表最多處理 120 萬筆去重過站資料，超過時請縮小日期範圍分批分析。獨立不良率推移的上限為每個日期或週 30 萬筆、每月 120 萬筆。

## 本機建置

執行 `npm ci`，建立 `.venv` 並安裝 `requirements.txt`。執行 `npm run build`，建置輸出位於 `dist/`。
